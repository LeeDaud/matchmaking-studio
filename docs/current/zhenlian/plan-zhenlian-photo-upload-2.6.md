## 一、这份文档解决什么问题

聚合版 `2.6` 指出当前照片上传只能拖拽文件，手机端和电脑端体验都不好。这是一个看似简单但直接影响红娘日常工作效率的体验问题。

这份文档的作用是：

1. 明确照片上传在不同终端（手机/电脑）的完整交互方案
2. 明确照片与已冻结的材料语义边界（头像 / 生活照 / 认证材料 / 补充材料）的对齐
3. 明确照片上传的格式、大小、数量限制
4. 明确照片管理（排序、删除、设为头像）的基本操作
5. 明确第一阶段的实现范围

一句话：

**本文不是再重复"要优化上传"，而是把聚合版 `2.6` 细化成覆盖多终端、多场景、多材料类型的完整照片管理方案。**

### 2.1 本文明确覆盖的范围

- 头像上传的交互方案

## 三、与已冻结对象的对齐

### 3.1 四类材料语义边界

导入与资料卡冻结 v1 已明确四类材料：

| 材料类型 | 对应字段 | 归属对象 | 语义 |
|------|------|------|------|
| 头像 | `avatar_url` | `profile_materials` | 唯一识别头像 |
| 生活照 | `lifestyle_photo_urls` | `profile_materials` | 多张辅助图片 |
| 认证材料 | `certification_items[*].material_refs` | `profile_certifications` | 认证凭证文件 |
| 补充材料 | `supplemental_materials` | `profile_materials` | 其他类型文件 |

照片上传必须遵循这四类边界，不允许混用。

### 3.2 混用禁止规则

- 头像字段只存唯一识别图，不允许把生活照存入 `avatar_url`
- 生活照字段只存生活类辅助图，不允许存认证材料原图
- 认证材料图片通过认证流程上传，不通过照片管理入口上传

## 四、当前问题分析

### 4.1 聚合版指出的问题

- 只能拖拽文件上传
- 手机端无法直接从相册选择
- 电脑端必须先保存到桌面再拖入

### 4.2 补充分析的问题

| 问题 | 影响 | 优先级 |
|------|------|------|
| 只支持拖拽 | 手机端几乎无法使用 | P0 |
| 不支持从相册选择 | 红娘最常见的照片来源是微信聊天记录和朋友圈截图 | P0 |
| 不支持粘贴上传 | 电脑端从微信复制图片后无法直接粘贴 | P1 |
| 上传后无法调整顺序 | 生活照的展示顺序影响资料卡效果 | P1 |
| 上传后无法裁剪 | 头像需要裁剪为合适比例 | P2 |
| 无上传进度提示 | 大图片上传时用户不知道状态 | P1 |

## 五、头像上传方案

### 5.1 交互要求

| 终端 | 上传方式 | 说明 |
|------|------|------|
| 手机端 | 点击头像区域 → 弹出选择面板（拍照 / 从相册选择） | 标准移动端图片选择交互 |
| 电脑端 | 点击头像区域 → 弹出文件选择器 / 支持拖拽 / 支持粘贴 | 三种方式并存 |

### 5.2 头像特殊规则

| 规则 | 说明 |
|------|------|
| 数量 | 只能有一张头像 |
| 替换 | 上传新头像自动替换旧头像 |
| 裁剪 | 上传后弹出裁剪框，建议 1:1 比例 |
| 默认 | 未上传头像时显示性别默认头像 |
| 格式 | JPG / PNG / WEBP |
| 大小 | 单张不超过 10MB，上传后系统自动压缩生成缩略图 |

### 5.3 头像裁剪交互

```
上传图片
  ↓
弹出裁剪框（1:1 比例，可缩放和移动）
  ↓
点击"确认" → 保存裁剪后的图片到 avatar_url
点击"取消" → 放弃本次上传
```

第一阶段裁剪要求：

- 支持 1:1 比例裁剪
- 支持缩放和拖动
- 不要求旋转和滤镜

---

## 六、生活照上传方案

### 6.1 交互要求

| 终端 | 上传方式 | 说明 |
|------|------|------|
| 手机端 | 点击"添加照片"按钮 → 弹出选择面板（拍照 / 从相册选择，支持多选） | 一次可选多张 |
| 电脑端 | 点击"添加照片"按钮 → 文件选择器（支持多选）/ 拖拽多张 / 粘贴 | 三种方式并存 |

### 6.2 生活照规则

| 规则 | 说明 |
|------|------|
| 数量上限 | 建议 20 张 |
| 格式 | JPG / PNG / WEBP / HEIC（iPhone 原生格式） |
| 单张大小 | 不超过 15MB |
| 排序 | 支持拖拽排序，第一张为主展示图 |
| 删除 | 支持单张删除，删除前确认 |
| 批量操作 | 支持批量选择删除 |

### 6.3 生活照管理交互

```
照片网格展示（缩略图）
  ├─ 长按/右键 → 弹出操作菜单（设为头像 / 删除 / 查看大图）
  ├─ 拖拽 → 调整排序
  ├─ 点击 → 查看大图（支持左右滑动浏览）
  └─ 点击"添加" → 上传新照片
```

### 6.4 "设为头像"功能

生活照中的任意一张可以被设为头像：

- 点击"设为头像" → 弹出裁剪框 → 确认后替换当前头像
- 原生活照保留在生活照列表中，不因设为头像而删除
- 头像是裁剪后的副本，不影响生活照原图

## 七、认证材料图片上传

### 7.1 入口区分

认证材料图片不通过照片管理入口上传，而是通过认证流程上传：

- 在客户详情的"认证"区域，选择认证类型后上传对应材料
- 上传的图片进入 `profile_certifications.certification_items[*].material_refs`
- 不进入 `profile_materials` 的头像或生活照字段

### 7.2 认证材料上传交互

| 终端 | 上传方式 | 说明 |
|------|------|------|
| 手机端 | 点击"上传材料" → 拍照 / 从相册选择 | 证件类建议拍照 |
| 电脑端 | 点击"上传材料" → 文件选择器 / 拖拽 | 支持 PDF 和图片 |

### 7.3 认证材料特殊规则

| 规则 | 说明 |
|------|------|
| 格式 | JPG / PNG / PDF |
| 大小 | 单个文件不超过 20MB |
| 数量 | 每种认证类型最多 5 个文件 |
| 预览 | 上传后可预览，但不支持编辑 |
| 安全 | 上传后不可公开访问，需权限验证 |

## 八、通用上传体验要求

### 8.1 上传进度

| 状态 | 展示 |
|------|------|
| 上传中 | 进度条 + 百分比 |
| 上传成功 | 缩略图展示 + 成功提示 |
| 上传失败 | 错误提示 + 重试按钮 |
| 压缩中 | "正在处理..." 提示 |

### 8.2 图片压缩策略

| 场景 | 压缩规则 |
|------|------|
| 头像 | 生成 200x200 和 80x80 两个缩略图 |
| 生活照 | 保留原图 + 生成 800px 宽度的展示图 + 200px 宽度的缩略图 |
| 认证材料 | 保留原图，不压缩（需保证材料清晰度） |

### 8.3 HEIC 格式兼容

iPhone 拍摄的照片默认为 HEIC 格式，系统需要：

- 上传时自动转换为 JPG
- 转换过程对用户透明
- 转换后保持合理画质

### 8.4 粘贴上传（电脑端）

- 在照片上传区域获得焦点时，支持 Ctrl+V / Cmd+V 粘贴图片
- 从微信、QQ 等聊天工具复制的图片可直接粘贴
- 粘贴后立即开始上传，无需额外确认

## 九、第一阶段实现优先级

### 9.1 P0 必须实现

- 手机端从相册选择上传（头像 + 生活照）
- 电脑端点击选择文件上传（头像 + 生活照）
- 电脑端拖拽上传
- 头像 1:1 裁剪
- 上传进度提示
- 基本的格式和大小校验

### 9.2 P1 建议实现

- 电脑端粘贴上传
- 生活照拖拽排序
- 生活照"设为头像"
- HEIC 格式自动转换
- 批量上传（一次选多张）

### 9.3 P2 后续实现

- 图片旋转
- 图片滤镜/美化
- 智能裁剪建议
- 图片质量检测（模糊检测）

## 十、本文对应的验收标准

1. 手机端和电脑端的上传交互方案可直接指导前端实现
2. 头像、生活照、认证材料三类图片的上传入口和存储落点清晰区分
3. 格式、大小、数量限制明确
4. 上传进度和异常处理完整
5. 与已冻结的材料语义边界无冲突
6. 第一阶段实现范围明确，不过度设计

## 十一、当前结论

基于聚合版 `2.6` 的原始需求，我当前的完整理解是：

1. 照片上传体验优化的核心是"让红娘能用最自然的方式把照片传上来"，不是做一个图片编辑器
2. 手机端从相册选择是最高优先级——红娘的照片大多来自微信聊天记录
3. 头像和生活照必须严格区分语义，不能混用
4. 认证材料图片走认证流程，不走照片管理入口
5. 第一阶段重点是打通基本上传链路，排序和编辑能力可以递进补全
